PoC — Agoda PCI payment page executes attacker-supplied JavaScript inside the card-entry origin

gwpci.agoda.com/app/payment/index-v4.html's Content-Security-Policy frame-ancestors allow-list includes *.wl44.solution.net and *.wl54.solution.net — a domain Agoda does not control (see the submitted report for the RDAP/DNS/certificate-transparency evidence). This page plays the role of that untrusted framing origin. The right-hand iframe below is running Agoda's own, completely unmodified client-side code, saved verbatim from a live request to the real page. Nothing on Agoda's infrastructure is contacted at any point in this demo.

What you're watching

  1. The iframe on the right loads Agoda's real, unmodified page logic.
  2. That code asks document.location.ancestorOrigins[0] — i.e. this page — who is framing it, then fetches <that origin>/getClientSideAssets?page=ccform from it.
  3. This page (the "attacker") answers with a manifest pointing at payload.js, also hosted on this same origin.
  4. Agoda's own code injects that script into its own document with a plain <script> tag — full DOM access, PCI origin.
  5. The injected script renders a card form and reads it back out, proving real data capture, not just script execution.
